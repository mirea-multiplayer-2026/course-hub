Практика 4. Dedicated Server и игровой цикл

Уважаемый студент! В этой практике вы выйдете за пределы редактора Unity. Вам понадобится WSL 2 с установленным Ubuntu. Если WSL ещё не настроен, установите его заранее командой wsl --install в PowerShell от имени администратора.

Цель

Собрать серверный билд под Linux, запустить его в WSL и реализовать полный игровой цикл:

  • настроить Unity для сборки Dedicated Server (Linux);
  • запустить headless-сервер в WSL 2 (Ubuntu);
  • подключить Windows-клиент к Linux-серверу по локальному IP;
  • реализовать лобби с ожиданием игроков и автоматическим стартом матча;
  • реализовать экран результатов и перезапуск цикла.

Ожидаемый результат

После выполнения практики:

  • headless-сервер запущен в консоли Linux (чёрное окно WSL);
  • Windows-клиенты подключаются к серверу по IP;
  • клиенты ожидают в лобби, пока не наберётся нужное количество игроков;
  • после старта матча идёт игровой процесс с подсчётом очков;
  • по окончании матча — экран результатов, затем возврат в лобби.

Подготовка

  1. Установите WSL 2 и дистрибутив Ubuntu, если ещё не установлены.
  2. В Unity Hub добавьте модуль Linux Dedicated Server Build Support для вашей версии Unity.
  3. Убедитесь, что в проекте есть рабочий FishNet-проект из Практики 3.
  4. Проверьте, что Windows Firewall не блокирует UDP-порт, используемый транспортом (по умолчанию 7770).

Проверь

Команда wsl --list --verbose показывает Ubuntu со статусом Running. В Unity установлен модуль Linux Server Build Support.

Этап 1. Headless-билд под Linux

Соберите серверную версию игры, которая работает без графики.

  • В Unity выберите File → Build Settings.
  • Переключите платформу на Dedicated Server, целевая ОС — Linux.
  • Добавьте в билд нужные сцены (минимум: меню и игровая сцена).
  • Добавьте логику автоматического запуска сервера при headless-режиме (без UI).
  • Нажмите Build и сохраните билд в удобную папку.
Подсказка: автозапуск сервера в headless-режиме

При запуске Dedicated Server нет экрана и UI. Сервер должен стартовать автоматически.

using FishNet;
using UnityEngine;

public class ServerAutoStart : MonoBehaviour
{
    private void Start()
    {
        // Application.isBatchMode == true, когда Unity запущен без графики.
        if (Application.isBatchMode)
        {
            Debug.Log("[Server] Headless mode detected. Starting server...");
            InstanceFinder.ServerManager.StartConnection();
        }
    }
}

Проверь

В папке билда есть исполняемый файл для Linux. Файл имеет расширение .x86_64 или без расширения.

Этап 2. Запуск в WSL и подключение клиента

Запустите собранный сервер в WSL и подключите к нему клиент из Windows.

  • Скопируйте папку билда в файловую систему WSL или запустите прямо из Windows-пути.
  • В терминале WSL дайте файлу права на выполнение: chmod +x ./GameServer.x86_64.
  • Запустите сервер: ./GameServer.x86_64 -batchmode -nographics.
  • Узнайте IP-адрес WSL: hostname -I.
  • В клиенте (Windows Editor или билд) укажите этот IP и подключитесь.
Подсказка: команды для запуска в WSL 
# Перейти в папку с билдом
cd /mnt/e/Builds/GameServer

# Дать права на запуск
chmod +x ./GameServer.x86_64

# Запустить сервер
./GameServer.x86_64 -batchmode -nographics

# В другом терминале WSL — узнать IP
hostname -I
# Пример вывода: 172.25.160.1

Проверь

В консоли WSL видны логи сервера. Windows-клиент подключается по IP, игрок спавнится на сцене.

Этап 3. Лобби и старт матча

Сервер должен ждать нужное количество игроков перед началом матча.

  • Создайте серверный скрипт GameManager, который отслеживает количество подключённых игроков.
  • Задайте лимит (например, 2 игрока) для старта матча.
  • Пока лимит не достигнут — клиенты видят экран ожидания с количеством подключённых.
  • При достижении лимита сервер оповещает клиентов о начале матча.
  • На клиентах скрывается экран ожидания и начинается игровой процесс.
Подсказка: каркас GameManager

Сервер управляет состоянием матча. Клиенты получают обновления через [SyncVar] или [ObserversRpc].

using FishNet;
using FishNet.Connection;
using FishNet.Object;
using FishNet.Object.Synchronizing;
using UnityEngine;

public class GameManager : NetworkBehaviour
{
    [SerializeField] private int _requiredPlayers = 2;

    [SyncVar(OnChange = nameof(OnGameStateChanged))]
    public GameState CurrentState = GameState.WaitingForPlayers;

    [SyncVar]
    public int ConnectedPlayers = 0;

    public enum GameState
    {
        WaitingForPlayers,
        InProgress,
        ShowingResults
    }

    public override void OnStartServer()
    {
        base.ServerManager.OnRemoteConnectionState += OnPlayerConnectionChanged;
    }

    private void OnPlayerConnectionChanged(
        NetworkConnection conn,
        FishNet.Transporting.RemoteConnectionStateArgs args)
    {
        if (!base.IsServerInitialized) return;

        // Пересчитываем игроков.
        ConnectedPlayers = base.ServerManager.Clients.Count;

        if (CurrentState == GameState.WaitingForPlayers
            && ConnectedPlayers >= _requiredPlayers)
        {
            StartMatch();
        }
    }

    private void StartMatch()
    {
        CurrentState = GameState.InProgress;
        Debug.Log("[Server] Match started!");
    }

    private void OnGameStateChanged(
        GameState oldValue, GameState newValue, bool asServer)
    {
        // Клиенты реагируют на смену состояния — переключают UI.
        Debug.Log($"Game state changed: {oldValue} -> {newValue}");
    }
}

Проверь

При подключении первого клиента он видит «Ожидание игроков: 1/2». При подключении второго — матч стартует автоматически.

Этап 4. Игровой цикл и результаты

Добавьте завершение матча, подсчёт результатов и перезапуск цикла.

  • Добавьте условие завершения матча: таймер (например, 60 секунд) или достижение счёта (первый до 3 фрагов).
  • По завершении сервер переводит состояние в ShowingResults.
  • Клиенты показывают экран результатов с итоговым счётом каждого игрока.
  • Через несколько секунд (или по нажатию кнопки) сервер сбрасывает счёт, возвращает состояние в WaitingForPlayers и перезапускает цикл.
Подсказка: завершение матча и перезапуск 
// Добавить в GameManager:

[SyncVar]
public float MatchTimer = 60f;

private void Update()
{
    if (!base.IsServerInitialized) return;
    if (CurrentState != GameState.InProgress) return;

    MatchTimer -= Time.deltaTime;

    if (MatchTimer <= 0f)
    {
        EndMatch();
    }
}

private void EndMatch()
{
    CurrentState = GameState.ShowingResults;
    Debug.Log("[Server] Match ended! Showing results...");

    // Через 5 секунд возвращаемся в лобби.
    Invoke(nameof(ResetToLobby), 5f);
}

private void ResetToLobby()
{
    // Сбросить очки всех игроков.
    foreach (var conn in base.ServerManager.Clients.Values)
    {
        foreach (var nob in conn.Objects)
        {
            PlayerNetwork pn = nob.GetComponent<PlayerNetwork>();
            if (pn != null)
            {
                pn.HP = 100;
                pn.Score = 0;
            }
        }
    }

    MatchTimer = 60f;
    CurrentState = GameState.WaitingForPlayers;
    Debug.Log("[Server] Lobby reset. Waiting for players...");
}

Проверь

Полный цикл: ожидание → матч (60 сек) → экран результатов → возврат в лобби. Всё повторяется без перезапуска сервера.

Что нужно реализовать самостоятельно

  • скрипт автоматического запуска сервера в headless-режиме;
  • сборку Dedicated Server билда под Linux;
  • запуск сервера в WSL и подключение Windows-клиента;
  • серверную логику ожидания игроков и автостарта матча;
  • UI лобби с отображением количества подключённых игроков;
  • условие завершения матча (таймер или счёт);
  • экран результатов с итоговым счётом;
  • перезапуск цикла без перезапуска серверного процесса.

Требования к сдаче

  • Продемонстрировать запуск headless-сервера в консоли WSL (Ubuntu).
  • Показать подключение Windows-клиента к Linux-серверу по IP.
  • Показать экран ожидания в лобби с количеством подключённых игроков.
  • Показать автоматический старт матча при достижении лимита игроков.
  • Показать игровой процесс с подсчётом очков/таймером.
  • Показать экран результатов по окончании матча.
  • Показать автоматический возврат в лобби для нового раунда.
  • Предоставить видео полного цикла: запуск сервера → лобби → матч → результаты → лобби.
  • Предоставить ссылку на Git-репозиторий проекта.
