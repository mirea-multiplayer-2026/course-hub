Лекция 3. Движение, Ownership и стрельба

Переход от теории к рабочему multiplayer-геймплею

Эта лекция соединяет фундамент из первых двух занятий с тем, что реально нужно в проекте: движение игрока через NetworkTransform, корректная работа IsOwner, камера только для владельца, серверный спавн объектов и полный цикл стрельбы с валидацией на сервере.

2. NetworkTransform и Jitter Buffer

NetworkTransform нужен не просто для “сделать синхронизацию”, а для контролируемой передачи именно тех координат и углов, которые критичны для жанра.

2D-платформер

Синхронизируйте Position X/Y и Rotation Z. Остальные оси в большинстве сцен не дают полезного сигнала.

3D-шутер

Обычно достаточно Position X/Y/Z и Rotation Y. Локальный pitch часто живёт отдельно в камере.

Гонки и физика

Нужны все оси позиции и вращения. Если движение строится на физике, смотрите в сторону NetworkRigidbody.

Почему движение может быть плавным даже при нестабильной сети

Jitter Buffer намеренно показывает не самый свежий пакет, а немного более старое состояние из буфера. Это добавляет небольшую визуальную задержку, но убирает рывки при неравномерном приходе пакетов.

  • Без буфера рендер зависит от случайных провалов сети.
  • С буфером клиент почти всегда имеет следующую точку для интерполяции.
  • Цена подхода: +50-100 мс отображаемой задержки, выигрыш: предсказуемая плавность.

NetworkTransform vs NetworkRigidbody

  • CharacterController, лифт, дверь, платформа: используйте NetworkTransform.
  • Мяч, физический снаряд, машина с Rigidbody: чаще подходит NetworkRigidbody.
  • Если физика и ручная запись позиции начинают спорить друг с другом, объект на клиентах дёргается.

3. Ownership, ChangeOwnership и жизненный цикл

IsOwner отвечает на вопрос: “этот объект принадлежит текущему клиенту?”. Для локального ввода это базовая проверка, без которой весь контроль рассыпается.

private void Update()
{
    if (!IsOwner) return;

    float h = Input.GetAxis("Horizontal");
    float v = Input.GetAxis("Vertical");

    Vector3 move = new Vector3(h, 0f, v);
    transform.Translate(move * (5f * Time.deltaTime), Space.World);
}

Когда менять владельца объекта

Смена владельца нужна, когда интерактивный объект должен перейти под контроль конкретного клиента: машина после посадки, предмет после подбора, камера-спектатор после смерти.

public void AssignVehicleToDriver(NetworkObject vehicle, ulong newClientId)
{
    if (!IsServer) return;

    vehicle.ChangeOwnership(newClientId);
}

Жизненный цикл сетевого объекта

  • Instantiate() создаёт объект локально, но ещё не вводит его в сеть.
  • NetworkObject.Spawn() публикует объект для остальных клиентов.
  • OnNetworkSpawn() вызывается, когда сетевой контекст уже готов и можно читать IsOwner.
  • OnNetworkDespawn() нужен для отписки и очистки зависимостей перед уничтожением.
Топ-3 ошибки и их исправление

Ошибка 1: читать ввод без if (!IsOwner) return;. Результат: несколько клиентов управляют одним объектом.

Ошибка 2: делать сетевую инициализацию в Start(). В этот момент объект ещё может не быть заспавнен в сети.

Ошибка 3: подписаться на событие в OnNetworkSpawn() и забыть отписаться в OnNetworkDespawn().

public override void OnNetworkSpawn()
{
    if (!IsOwner) return;

    SetupCamera();
    score.OnValueChanged += OnScoreChanged;
}

public override void OnNetworkDespawn()
{
    score.OnValueChanged -= OnScoreChanged;
}

4. Камера в мультиплеере

Главное правило: камера не должна пытаться следовать за каждым игроком. Её настраивает только локальный владелец объекта, и лучше делать это после сетевого спавна.

  • FPS: камера как дочерний объект головы, активируется только у IsOwner.
  • TPS: камера хранит смещение и обновляется в LateUpdate().
  • Top-down: камера может следить за зоной или центром группы, а не за локальной моделью один в один.
using Unity.Netcode;
using UnityEngine;

public class PlayerCamera : NetworkBehaviour
{
    [SerializeField] private Vector3 _offset = new Vector3(0f, 2.2f, -3.6f);
    [SerializeField] private float _lookHeight = 1.25f;

    private Camera _mainCamera;

    public override void OnNetworkSpawn()
    {
        if (!IsOwner) return;

        _mainCamera = Camera.main;
        Cursor.lockState = CursorLockMode.Locked;
        Cursor.visible = false;
    }

    private void LateUpdate()
    {
        if (!IsOwner || _mainCamera == null) return;

        _mainCamera.transform.position = transform.position + transform.rotation * _offset;
        _mainCamera.transform.LookAt(transform.position + Vector3.up * _lookHeight);
    }

    public override void OnNetworkDespawn()
    {
        if (!IsOwner) return;

        Cursor.lockState = CursorLockMode.None;
        Cursor.visible = true;
    }
}

Критический нюанс

Cursor.lockState и любые операции с Camera.main должны выполняться только внутри ветки IsOwner. Иначе вы заблокируете мышь и камеру сразу у всех клиентов.

5. Серверный спавн и SpawnWithOwnership

Обычный Instantiate() создаёт объект только локально. Чтобы объект увидели остальные, сервер обязан заспавнить NetworkObject в сети.

[ServerRpc]
private void SpawnPickupServerRpc(Vector3 position)
{
    GameObject instance = Instantiate(pickupPrefab, position, Quaternion.identity);
    NetworkObject networkObject = instance.GetComponent<NetworkObject>();

    networkObject.Spawn();
}

Когда нужен SpawnWithOwnership

Если объект с момента рождения должен быть привязан к конкретному клиенту, сразу назначайте владельца.

[ServerRpc]
private void SpawnProjectileServerRpc(Vector3 position, Vector3 direction, ServerRpcParams rpcParams = default)
{
    Quaternion rotation = Quaternion.LookRotation(direction);
    GameObject projectile = Instantiate(projectilePrefab, position, rotation);

    projectile.GetComponent<NetworkObject>()
        .SpawnWithOwnership(rpcParams.Receive.SenderClientId);
}

Удаление объекта

  • Destroy() без Despawn() ломает согласованность между сервером и клиентами.
  • Корректная последовательность для сетевого удаления: NetworkObject.Despawn(destroy: true).
  • И спавн, и деспавн должны инициироваться сервером.

6. Безопасность RPC и серверная валидация

Клиент должен отправлять намерение, а не окончательное решение. Если сервер слепо доверяет входным параметрам RPC, игра получает спидхак, телепорт, one-shot урон и дубликацию предметов.

Спидхак

Клиент присылает скорость в несколько раз выше допустимой, сервер не проверяет и принимает движение.

Телепорт

Клиент сообщает позицию за стеной или вне карты, сервер не валидирует траекторию и разрешает перенос.

Урон без ограничений

Если доверять числу урона из пакета, клиент может превратить любой выстрел в мгновенное убийство.

[ServerRpc]
private void ShootServerRpc(Vector3 direction, ServerRpcParams rpcParams = default)
{
    ulong clientId = rpcParams.Receive.SenderClientId;

    if (!IsAlive) return;
    if (currentAmmo <= 0) return;
    if (Time.time < lastShotTime + shootCooldown) return;
    if (direction.magnitude < 0.9f || direction.magnitude > 1.1f) return;

    lastShotTime = Time.time;
    currentAmmo--;

    Quaternion rotation = Quaternion.LookRotation(direction.normalized);
    GameObject projectile = Instantiate(projectilePrefab, muzzle.position, rotation);
    projectile.GetComponent<NetworkObject>().SpawnWithOwnership(clientId);

    PlayShotClientRpc();
}

Такая форма с ранними return делает правила сервера явными и не раскрывает клиенту внутреннюю логику отказа больше, чем нужно.

7. Полный цикл стрельбы

Когда все элементы лекции соединяются, получается простая, но надёжная цепочка: владелец читает ввод, сервер создаёт сетевой объект, клиенты видят результат, сервер применяет урон и удаляет снаряд.

  1. Клиент-владелец: читает нажатие и вызывает ShootServerRpc().
  2. Сервер: валидирует состояние игрока, кулдаун, направление и наличие патронов.
  3. Сервер: создаёт снаряд через Instantiate + SpawnWithOwnership.
  4. Все клиенты: получают заспавненный объект и проигрывают эффект выстрела.
  5. Сервер: обрабатывает попадание, уменьшает HP и деспавнит снаряд.
Пример PlayerShooting.cs 
using Unity.Netcode;
using UnityEngine;

public class PlayerShooting : NetworkBehaviour
{
    [SerializeField] private GameObject projectilePrefab;
    [SerializeField] private Transform muzzle;
    [SerializeField] private AudioClip shootSound;
    [SerializeField] private float shootCooldown = 0.3f;

    private float lastShotTime;

    private void Update()
    {
        if (!IsOwner) return;
        if (!Input.GetKeyDown(KeyCode.Mouse0)) return;

        ShootServerRpc(muzzle.forward);
    }

    [ServerRpc]
    private void ShootServerRpc(Vector3 direction, ServerRpcParams rpcParams = default)
    {
        if (Time.time < lastShotTime + shootCooldown) return;

        lastShotTime = Time.time;

        Quaternion rotation = Quaternion.LookRotation(direction.normalized);
        GameObject projectile = Instantiate(projectilePrefab, muzzle.position, rotation);
        projectile.GetComponent<NetworkObject>()
            .SpawnWithOwnership(rpcParams.Receive.SenderClientId);

        PlaySoundClientRpc(muzzle.position);
    }

    [ClientRpc]
    private void PlaySoundClientRpc(Vector3 worldPosition)
    {
        AudioSource.PlayClipAtPoint(shootSound, worldPosition);
    }
}
Пример Projectile.cs 
using Unity.Netcode;
using UnityEngine;

public class Projectile : NetworkBehaviour
{
    [SerializeField] private float speed = 20f;
    [SerializeField] private int damage = 25;

    private void Update()
    {
        transform.position += transform.forward * (speed * Time.deltaTime);
    }

    private void OnTriggerEnter(Collider other)
    {
        if (!IsServer) return;

        if (other.TryGetComponent(out PlayerHealth health) &&
            other.TryGetComponent(out NetworkObject targetObject))
        {
            if (targetObject.OwnerClientId == OwnerClientId) return;

            health.TakeDamage(damage);
        }

        NetworkObject.Despawn(destroy: true);
    }
}

8. Чек-лист и подготовка к Практике 2

Перед переходом к практической работе студент должен уметь быстро прогнать короткий список самопроверки.

  1. Я понимаю, когда использовать NetworkTransform, а когда NetworkRigidbody.
  2. Я знаю, что Jitter Buffer добавляет плавность ценой небольшой задержки отображения.
  3. Я могу объяснить, зачем нужен ChangeOwnership() и кто имеет право его вызывать.
  4. Я не инициализирую сетевую логику в Start(), если она зависит от IsOwner.
  5. Камера и курсор меняются только у локального владельца объекта.
  6. Сетевой объект появляется через Spawn() и удаляется через Despawn(true).
  7. Любой важный ServerRpc сначала валидирует входные данные.

Если что-то не работает

Проверьте три места в первую очередь: есть ли IsOwner перед вводом, есть ли IsServer в серверной логике попадания и не спрятана ли инициализация в Start() вместо OnNetworkSpawn().
